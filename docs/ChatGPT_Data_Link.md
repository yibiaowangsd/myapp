# 在 ChatGPT 中读取「我」的数据

数据通道是 **Android App → 你自己的私有 GitHub 仓库 → ChatGPT 的 GitHub 连接**。
App 没有新增会话，手机也不需要 OpenAI API 密钥。它提供一个持续更新、可按日期查询的历史来源。2.2新增的可选 DeepSeek 回顾使用单独配置的 DeepSeek API Key，相关记忆经此通道共享。

## 一次性配置

1. 在 GitHub 新建独立的 **Private** 仓库，例如 `你的用户名/wo-life-data`。不要将记录存放在公开的 App 源码仓库。
2. 创建 fine-grained personal access token，仅选择这个数据仓库，并授予 **Contents: Read and write**。令牌只填写在手机上，不提交到源码或发送到聊天。
3. App 右上角 **设置 → 数据互通**，输入仓库与令牌，点击 **保存并同步**。
4. 确保 ChatGPT 的 GitHub 连接获准访问该私有仓库。App 的上传令牌和 ChatGPT 的 GitHub 授权是两套独立凭据。
5. 点击 App 的 **复制连接说明**，在 ChatGPT 中粘贴一次，让当前对话知道仓库地址。示例：

   > 我的生活记录在私有仓库 `你的用户名/wo-life-data`。请通过 GitHub 先读取 `wo/index.json`，再读取其中相关日期的文件，并结合我们当前可用的聊天记忆分析。

以后可以问“看看我最近一周的活动变化”“这几天的手机使用有什么规律”。需要新数据时，应重新读取索引和对应日文件。

## 文件协议

| 路径 | 内容 |
| --- | --- |
| `wo/index.json` | 协议版本、归档时区、更新时间、已成功上传的日期、日文件路径及内容哈希 |
| `wo/days/YYYY-MM-DD.json` | 当天摘要、事实、指标、事件时间与标题、来源、覆盖情况和缺失说明 |
| `wo/memory.json` | 本人填写的偏好、DeepSeek 历史观察与最近回顾；由索引 `memory` 条目指向，推断不等于确认事实 |
| `wo/parts/YYYY-MM-DD/HASH/NNNNN.json` | 2.2.1 新增：较大日期的 JSON 分片，由当天目录文件依次引用 |

只有索引列出的日文件才应当作当前有效来源。先获取 `main` 的提交 SHA，随后读取索引、记忆及日文件时均指定该 SHA，避免读取过程中手机又更新目录。每次读取应注明使用的数据日期与 `asOfMs`；旧快照不代表实时手机状态。
没有记录或没有授权不等于没有活动；`assertion` 区分记录、确认和推测。

## 同步行为

- 默认关闭；完成配置后才开始上传。内容哈希不变的日期不重复提交。
- 本机记录变化后安排一次同步，并通过 WorkManager 约每30分钟补同步。网络、电量和 Android 后台策略可能延后，不能保证实时到达。
- 每批最多上传48个变化日期，剩余日期在后续同步继续处理；界面显示待同步数量。
- 2.2.1 将日文件、分片、记忆、索引及撤回操作放入同一 Git 提交，以非强制方式更新分支。上传对象过程中失败，当前分支的旧快照仍完整；分支发生并发变化时重新读取目录再重试。
- 单个日文件超过 524288 **UTF-8 字节**时，保留日期入口文件，改为 `format: wo-day-parts` 的分片目录。分片约 240KiB，每份都是合法 JSON，不丢弃记录。没有整天 512KB 的总容量限制。
- 读取分片日期时依次读取目录 `parts`，用 SHA-256 核对每个分片；按 `fields` 的顺序恢复顶层字段，`arrays` 中列出的数组按分片顺序连接，其他字段只能出现一次。日哈希为恢复后紧凑 JSON 去除 `asOfMs` 后的 SHA-256；普通旧日文件使用同样算法。若单条嵌套事实本身过大，目录使用 `format: wo-day-text-parts`：按顺序连接各分片的 `text` 字段，再解析为完整 JSON，仍须校验分片和日哈希。Unicode 字符不会在代理项中间切断。记忆哈希为文件原始 UTF-8 字节的 SHA-256。
- 兼容已有 v1 索引与普通日文件；2.2.1 发布 v2 索引。旧版 App 不支持 v2，应升级后继续同步。没有索引时会核对并接纳相同内容的旧日文件，避免从头重复上传。
- 无法生成或拆分的日期会计入待同步，不会阻止其他日期及记忆发布；暂缓的已有日期仍保留上一份有效快照。v2索引的 `pendingDates` 明确列出这些日期，读取时应说明其快照尚未更新；涉及这些日期的记忆观察不能视为已由最新日文件复核。
- 网络错误、HTTP 408/429/5xx 及明确的限流会进行有限退避重试；权限错误直接提示，冲突重新开始一批。后台失败会持久显示阶段性错误，不会沿用成功文案；只有没有待同步日期时更新“最近完整成功”时间。
- 上传之前确认目标仓库是私有仓库；公开仓库会被拒绝。
- 不上传相册原图、精确坐标、本机照片 URI 或通知正文。日文件是结构化生活记录，不是完整数据库备份。
- 本地删除的数据在后续同步中更新或移出当前索引。GitHub 提交历史仍可能保留旧版本；暂停同步不会删除远端文件。
- 备份归档不包含同步令牌，换手机后需重新配置。

## “带记忆”的含义

历史日文件持续保存，2.2的共享记忆另保存偏好和历史观察。ChatGPT 可以在获得仓库访问权限时读取两者，并结合当前对话和当前可用的账号记忆作答。详见 [DeepSeek 与长期记忆](DeepSeek_Memory.md)。
这不等于将 App 数据自动写入 ChatGPT 账号记忆，也不会在没有提问或安排任务时自动分析手机数据。
跨对话使用时，仍需让相关聊天知道数据仓库；保存在项目说明中也可以。

## 联通验收

手机显示同步成功后，在 ChatGPT 中实际读取私有仓库的 `wo/index.json` 和一个真实日文件。
确认日期、事件和指标与手机一致；修改一个片段后再次同步并读取，确认内容更新。
完成这一步之前，只能称为“同步功能已实现”，不能称为手机数据已经与 ChatGPT 连通。
