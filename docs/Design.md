# “我” Android 应用设计说明 · 当前实现

文档更新：2026-10-15（Asia/Shanghai）

对应应用：1.0.1，versionCode 2，`com.personal.wo`

状态：首版安装测试工程，尚未完成全部生产发布验收。

本文描述本次源码中已经落地的设计和实现边界。原始需求与验收基线保存在 [Design_Baseline.md](Design_Baseline.md)，开发入口见 [Development.md](Development.md)，实际测试证据见 [Verification.md](Verification.md)。

## 1. 产品与使用闭环

“我”把手机公开系统接口能够提供的生活证据整理成每日记录。首次配置来源权限并开始记录后，采集器持续或定期补采，事件引擎在本地形成片段、四轨时间轴、每日摘要和历史规律。本人可以检查来源、确认或修正片段、命名地点、收藏、暂停、删除和导出备份。

应用没有账号和必需的服务器。数据来源缺失、权限未授予或系统中断会留下明确的未知值或覆盖缺口。演示数据使用独立内存样本，带演示标识，不写入真实记录。

## 2. 两个构建版本

| 项目 | personalOffline · 离线版 | personalEnhanced · 增强版 |
|---|---|---|
| 自动记录、今天、回看、规律、修正、删除与加密备份 | 支持 | 支持 |
| 本地确定性摘要 | 支持 | 支持 |
| INTERNET 权限 | 移除 | 声明 |
| 事实整理端点 | 不启用 | 本人配置 HTTPS 端点后手动触发 |
| 网络输出用途 | 无 | 只调整已有本地摘要句子的排序 |
| 请求限制 | 无网络请求 | 当前实际归档日最多 3 次；查看旧日期仍计入今天的额度 |

两个版本共用 applicationId、数据库结构和个人 Release 签名，可以覆盖安装并保留数据，不能作为两个独立应用同时安装。Debug 使用调试签名，不能直接覆盖个人签名的 Release。

增强接口发送已有事实的 ID、类型和展示值；不发送照片原图、原始通知正文或精确坐标。返回契约是 `{"factIds":["已有ID"]}`，最多 4 个不重复且已知的 ID。最终文案仍由本地生成。请求失败或返回不合法时保留本地摘要。当前需要符合应用自定义协议的端点或服务端适配，不能直接假定兼容任意厂商的聊天接口。

## 3. 信息架构与页面

| 页面 | 当前交互与展示 |
|---|---|
| 今天 | 每日事实摘要、地点/活动/数字/生活四轨总览、重点片段、来源缺口、演示入口 |
| 回看 | 月历、历史每日摘要、进入指定日期详情 |
| 日详情 | 小时桶时间轴、缩放、轨道筛选、片段列表、静音游标回放、离线足迹 |
| 搜索 | 中文/英文、地点/应用关键词、轨道筛选、近 90 天或全历史、分页加载 |
| 片段详情 | 来源依据、标题与时间修正、本人确认、收藏、地点命名、删除预览 |
| 规律 | 有足够有效样本和覆盖率时展示变化；样本不足显示积累中 |
| 设置 | 来源权限与开关、通知解析允许列表、应用/时段排除、暂停/停止、查看身份验证、导出/恢复与诊断 |

视觉使用纸白底色与森林绿主色，并支持深色模式。底部导航保留页面状态和滚动位置。回放在界面离开前台时停止。足迹为本地投影示意，只连接间隔不超过 5 分钟的有效位置，不加载在线地图瓦片；跨 180° 经线使用经度解包。

## 4. 来源与事实口径

| 来源 | 接入方式 | 当前边界 |
|---|---|---|
| 地点 | LocationManager 被动/网络定位与有界 GNSS 短请求 | 位置缺口不补造路线；模拟位置和低质量证据不作为可靠足迹 |
| 硬件步数/运动 | 步数累计传感器、显著运动传感器 | 重启或恢复后重新建基线，不跨暂停估算步数 |
| 应用与屏幕活动 | UsageEvents 增量读取 | 同包 Activity 切换合并；并发应用取区间并集；未知尾部不计成全天 |
| 通知 | NotificationListenerService | 仅明确选定包名解析脱敏正文；其余保存元数据；线索不直接变成经历 |
| 媒体 | MediaSession 回调 | 记录公开播放状态；暂停/中断结束可信连续性；不控制播放和音频焦点 |
| 照片/视频 | MediaStore 分页索引 | 分清照片/视频与拍摄/添加时间；无拍摄时间不声称拍摄；不复制原图 |
| 日历 | CalendarContract Instances | 显示为计划；取消项对账；不声称本人实际参加 |
| 健康 | 可选 Health Connect | 步数、运动、睡眠来自获授权记录；当前按有界 7 日快照对账 |
| 窗口切换 | 可选 AccessibilityService | 仅包名与时间元数据；不读取内容、不执行手势；尚未独立转成活动时长 |

事实断言区分系统记录、推断、本人确认、计划与未知。没有权限不显示为 0；手机未交互不推断为睡眠；片段详情能展示来源证据。每日本地摘要最多 4 句，重点片段最多 8 项。规律比较主要地点开始、晚间应用活动和媒体开始时段，要求历史基线至少 10 个有效样本、近期至少 4 个样本以及相应覆盖率门槛，不进行心理诊断或效率评分。

## 5. 本地架构与处理

工程采用 `:app` 与纯 Kotlin/JVM `:core` 两个模块。`:core` 负责模型、半开时间区间、排除规则、会话/停留/媒体构造、事实摘要与规律；`:app` 负责公开系统来源、调度、加密数据库、备份与 Compose 界面。

系统回调进入容量 512 的有界队列，批处理最多 100 条，普通合并窗口约 4.5 秒，通知窗口约 1.5 秒。数据库写入通过单写入互斥控制；观察、来源游标和待重建窗口在事务内更新。日视图使用缓存与后台重建，内容发生变化时推进 revision。generation 用于拒绝暂停、删除或配置更新前的旧批次。

UsageEvents 与媒体会话不延长缺失边界；日历不参与实际出席判定。停留需要至少 3 个位置、持续至少 10 分钟、相邻缺口不超过 20 分钟，并按精度估计 80–300 米半径。原始证据过期后，保留最小片段证据与历史指标；删除排除仍作用于保留证据。

## 6. 后台与低干扰预算

只有实际位置/硬件步数能力可用且权限满足时，启动相应类型的前台记录服务，使用静默状态通知。应用不录音、不录像、不截图，不读键盘或剪贴板，不依赖 root、设备所有者权限或隐藏接口。

| 控制项 | 当前默认值或行为 |
|---|---|
| 可重放来源增量工作 | WorkManager 唯一周期任务，约 30 分钟 |
| 日视图重建 | 唯一任务，延迟约 5 分钟并合并变化 |
| 日维护 | 约每日一次，要求充电、电量及存储条件满足 |
| 停留候选 | 网络/被动位置约 3 分钟请求，最多 12 分钟，最小位移 0 米 |
| 已停留状态 | 约 15 分钟请求，最小位移 0 米 |
| 移动状态 | 约 2 分钟、100 米请求 |
| GNSS | 每次 20 秒、冷却 10 分钟、每小时 120 秒、每日 600 秒硬预算 |
| 电量/温度 | 低电量或温度升高时降级，严重条件进入被动模式；恢复有迟滞 |
| 中断恢复 | 记录不可补回的缺口，发出可点击恢复提示；从合法用户入口恢复服务 |

上述频率受 Android 后台调度影响，不能视为精确定时保证。CPU、内存、日耗电和 OEM 稳定性目标仍需真机测量。

## 7. 持久化、暂停与删除

Room V1 使用 SQLCipher 加密与 WAL，共 17 个实体，实际导出的结构位于 `app/schemas/`，可读 DDL 位于 `contracts/schema.sql`。Keystore 保护数据库秘密与来源键种子；来源唯一键经 HMAC 处理。应用排除 Android 自动备份中的私有数据，迁移使用本人主动的加密归档。

暂停/停止先持久化新的 generation 和排除区间，再释放来源；后续补采也必须经过同一过滤。删除同时清理相关观察、片段、证据、索引、修正和每日结果，并持久化时段或来源键排除，避免简单补采后重现。

| 保留与资源规则 | 当前实现 |
|---|---|
| 原始观察 | 30 天 |
| 通知正文/原始通知观察 | 7 天 |
| 诊断日志 | 7 天 |
| 非收藏片段 | 730 天 |
| 数据库软预算 | 800 MiB：降级通知正文及新照片索引 |
| 硬预算 | 约 1000 MiB 或可用空间低于 20 MiB：停止新增原始观察，标记缺口 |
| 故障处理 | 密钥不可用/数据库损坏时保留文件，不自动破坏性清库 |

## 8. 备份与增强协议

完整备份为 `.woarchive`：外层 `WOARCH01` 头、独立恢复码包装的随机 keyset、Tink `AES256_GCM_HKDF_1MB` 流式认证加密载荷。内部 ZIP 固定为 7 项，含 manifest、观察、片段、修正、地点、策略及每日视图；不含照片原图、原设备权限或 API 密钥。

恢复先完整认证到私有暂存文件，再检查固定文件名、重复/路径穿越、条目大小、计数和哈希，导入独立加密暂存数据库并检查完整性，最后在正式数据库单事务内替换。失败回滚；成功后保持停止状态，重新检查来源授权。跨设备原媒体 URI 清除，等待重新关联。

当前归档展开上限为 512 MiB；每类 JSONL 明细上限为 50,000 条。按范围完整备份的入口尚未实现。可读的每日 Markdown/JSON 导出默认移除通知正文、精确坐标和图片 URI。
