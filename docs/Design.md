本文描述本次源码中已经落地的设计和实现边界。原始需求与验收基线保存在 [Design_Baseline.md](Design_Baseline.md)，开发入口见 [Development.md](Development.md)，实际测试证据见 [Verification.md](Verification.md)。

## 1. 产品与使用闭环

“我”把手机公开系统接口能够提供的生活证据整理成每日记录。首次配置来源权限并开始记录后，采集器持续或定期补采，事件引擎在本地形成片段、生活时间线、每日图表和历史规律。本人可以检查来源、确认或修正片段、命名地点、收藏、暂停、删除和导出备份。

应用没有账号和必需的服务器。数据来源缺失、权限未授予或系统中断会留下明确的未知值或覆盖缺口。演示数据使用独立内存样本，带演示标识，不写入真实记录。

## 2. 两个构建版本

| 项目 | personalOffline · 离线版 | personalEnhanced · 增强版 |
|---|---|---|
| 自动记录、时间轴、回忆、生活趋势、修正、删除与加密备份 | 支持 | 支持 |
| 本地确定性摘要 | 支持 | 支持 |
| INTERNET 权限 | 移除 | 声明 |
| 事实整理端点 | 不启用 | 本人配置 HTTPS 端点后手动触发 |
| 网络输出用途 | 无 | 只调整已有本地摘要句子的排序 |
| 请求限制 | 无网络请求 | 当前实际归档日最多 3 次；查看旧日期仍计入今天的额度 |

两个版本共用 applicationId、数据库结构和个人 Release 签名，可以覆盖安装并保留数据，不能作为两个独立应用同时安装。Debug 使用调试签名，不能直接覆盖个人签名的 Release。

增强接口发送已有事实的 ID、类型和展示值；不发送照片原图、原始通知正文或精确坐标。返回契约是 `{"factIds":["已有ID"]}`，最多 4 个不重复且已知的 ID。最终文案仍由本地生成。请求失败或返回不合法时保留本地摘要。当前需要符合应用自定义协议的端点或服务端适配，不能直接假定兼容任意厂商的聊天接口。

## 3. 信息架构与页面

| 页面 | 当前交互与展示 |
|---|---|
| 首次打开 | 直接合并申请普通系统权限，再按需打开特殊访问设置；没有应用内二次确认 |
| 记录权限 | 一次申请未开启权限；单项点击直达系统；允许后刷新来源状态；保留拒绝与暂停选择 |
| 时间轴 | 按大事件与真实起止组织的双向景深转筒；随时间变化的背景、轴内照片、长应用、历史日期 |
| 事件详情 | 这一事件关联的影像和原始片段，包括期间收起的短应用使用 |
| 一天统计 | 右上角图表进入：日统计、小时图、应用时段 |
| 全部片段 | 从首页或一天统计进入完整时间线，支持日期切换、类别筛选和应用使用区间 |
| 连接 | 实际安装应用、通知正文选择、排除、来源授权和后台说明 |
| 回忆 | 适配屏幕宽度的月历、历史摘要、进入指定日期 |
| 日详情 | 按时间段分组、按类别筛选的事件列表；按需展开离线位置分布 |
| 搜索 | 关键词、类别筛选、90天或全历史、分页 |
| 片段详情 | 来源依据、修正与确认、收藏、地点命名、删除 |
| 我的 | 记录状态、来源权限、生活趋势、数据与隐私、示例入口 |
| 生活趋势 | 最近七天应用活动柱图；数据足够后展示历史规律 |
| 更多设置 | 通知解析允许列表、排除、停止、查看身份验证、导出恢复、诊断和可选增强端点 |

沿用Material图标、字体层级和圆角卡片。首页背景随当前浏览的事件时间，从晨光、白昼过渡到暮色与夜色；以归档时区为准，双向转动连续插值，深色模式保留色调并降低亮度。色调不代表实际天气或日出日落。底部固定“时间轴、回忆、连接、我的”，页面保留浏览位置。

首页聚焦一条横向转筒时间轴，每张卡片是一件有实际时间边界的大事件，不再按四个时段切分。停留、运动、睡眠或移动成为事件，相关照片与应用附在其中；独立影像按接近的拍摄/添加时间成组，相近长应用和媒体有界合并。标题只描述来源记录，推测仍标明推测，不从软件名称编造工作或学习。所有卡片使用共同画布、镜像offset及透视、缩放、淡出；透明原生Pager承担手势、状态与阅读语义，没有自动轮播。

应用默认单次实际观察至少10分钟，可选择5/10/20/30分钟。每段先判断门槛，多次短打开不凑门槛；重叠取并集，空档不计时。跨中午的同一会话保留完整。大事件合并有跨度上限，相关小记录只能归入包含它的事件，不被塞进远处的经历；其余记录通过首页“全部片段”查看。只有短记录时显示入口，不捏造大事件。详细规则见[1.6.0大事件时间轴](Event_Timeline_1.6.0.md)。

点击顶部日期选择过去日期，支持前一天、后一天、回到今天；首尾仍是相邻日期入口。回忆月历进入所选日期转筒，返回详情与统计保留日期及位置，切日载入不混显旧记录。底部以实际时间刻度选择事件，事件详情使用类型与主要片段ID组成的稳定键，区分同时开始的不同事情。

照片直接出现在轴内，详情可访问全部不同URI；从MediaStore读取真实缩略图，不复制原图，不可访问时显示提示。分清拍摄和添加时间。步数不虚分到事件，不将日累计步数当一次运动；完整记录和日统计保留原始口径。

一天统计保持独立入口，包含步数、停留片段数、关联影像数量、手机使用总量、小时图与实际应用区间。它不使用首页时长门槛；全部片段仍支持分类和日期筛选。此前纵向图文组件保留为回归参考。

直接授权完成标记独立于数据库，普通权限合并为一次系统请求，系统仍可能按权限组显示多个界面。特殊访问按队列逐页打开，返回或拒绝都会继续，单轮不重复。后台定位、可选健康与无障碍保持独立入口。已有暂停/停止状态保留；首次使用在系统流程结束后自动开始记录。详见[1.2.0修改说明](Daily_Recap_1.2.0.md)。

## 4. 来源与事实口径

| 来源 | 接入方式 | 当前边界 |
|---|---|---|
| 地点 | LocationManager 被动/网络定位与有界 GNSS 短请求 | 位置缺口不补造路线；模拟位置和低质量证据不作为可靠足迹 |
| 手机步数/运动 | 累计计步器（含唤醒/非默认传感器）、单步检测器兼容回退 | 先请求身体活动再确认设备能力；验证注册返回值；首样本建基线；不读取华为健康历史、不跨暂停估算 |
| 应用与屏幕活动 | UsageEvents 增量读取 | 同包 Activity 切换合并；并发应用取区间并集；未知尾部不计成全天 |
| 通知 | NotificationListenerService | 仅明确选定包名解析脱敏正文；其余保存元数据；线索不直接变成经历 |
| 媒体 | MediaSession 回调 | 记录公开播放状态；暂停/中断结束可信连续性；不控制播放和音频焦点 |
| 照片/视频 | MediaStore 分页索引 | 分清照片/视频与拍摄/添加时间；无拍摄时间不声称拍摄；不复制原图 |
| 日历 | CalendarContract Instances | 显示为计划；取消项对账；不声称本人实际参加 |
| 健康 | 可选 Health Connect | 步数、运动、睡眠来自获授权记录；当前按有界 7 日快照对账 |
| 窗口切换 | 可选 AccessibilityService | 仅包名与时间元数据；不读取内容、不执行手势；尚未独立转成活动时长 |

事实断言区分系统记录、推断、本人确认、计划与未知。没有权限不显示为 0；手机未交互不推断为睡眠；片段详情能展示来源证据。引擎保留最多4句事实摘要用于历史与导出；首页按这些片段呈现可转动的经历，统计页展示日汇总，完整记录通过时间线查看。规律比较主要地点开始、晚间应用活动和媒体开始时段，要求历史基线至少 10 个有效样本、近期至少 4 个样本以及相应覆盖率门槛，不进行心理诊断或效率评分。

## 5. 本地架构与处理

工程采用 `:app` 与纯 Kotlin/JVM `:core` 两个模块。`:core` 负责模型、半开时间区间、排除规则、会话/停留/媒体构造、事实摘要与规律；`:app` 负责公开系统来源、调度、加密数据库、备份与 Compose 界面。

系统回调进入容量 512 的有界队列，批处理最多 100 条，普通合并窗口约 4.5 秒，通知窗口约 1.5 秒。数据库写入通过单写入互斥控制；观察、来源游标和待重建窗口在事务内更新。日视图使用缓存与后台重建，内容发生变化时推进 revision。generation 用于拒绝暂停、删除或配置更新前的旧批次。

UsageEvents 与媒体会话不延长缺失边界；日历不参与实际出席判定。停留需要至少 3 个位置、持续至少 10 分钟、相邻缺口不超过 20 分钟，并按精度估计 80–300 米半径。原始证据过期后，保留最小片段证据与历史指标；删除排除仍作用于保留证据。

## 6. 后台与低干扰预算

只有实际位置/硬件步数能力可用且权限满足时，启动相应类型的前台记录服务，使用静默状态通知。应用不录音、不录像、不截图，不读键盘或剪贴板，不依赖 root、设备所有者权限或隐藏接口。

| 控制项 | 当前默认值或行为 |
|---|---|
| 可重放来源增量工作 | WorkManager 唯一周期任务，约 30 分钟 |
| 日视图重建 | 唯一任务，延迟约 5 分钟并合并变化 |
| 日维护 | 约每日一次，要求充电、电量及存储条件满足 |
| 停留候选 | 网络/被动位置约 3 分钟请求，最多 12 分钟，最小位移 0 米 |
| 已停留状态 | 约 15 分钟请求，最小位移 0 米 |
| 移动状态 | 约 2 分钟、100 米请求 |
| GNSS | 每次 20 秒、冷却 10 分钟、每小时 120 秒、每日 600 秒硬预算 |
| 电量/温度 | 低电量或温度升高时降级，严重条件进入被动模式；恢复有迟滞 |
| 中断恢复 | 记录不可补回的缺口，发出可点击恢复提示；从合法用户入口恢复服务 |

上述频率受 Android 后台调度影响，不能视为精确定时保证。CPU、内存、日耗电和 OEM 稳定性目标仍需真机测量。

## 7. 持久化、暂停与删除

Room V1 使用 SQLCipher 加密与 WAL，共 17 个实体，实际导出的结构位于 `app/schemas/`，可读 DDL 位于 `contracts/schema.sql`。Keystore 保护数据库秘密与来源键种子；来源唯一键经 HMAC 处理。应用排除 Android 自动备份中的私有数据，迁移使用本人主动的加密归档。

暂停/停止先持久化新的 generation 和排除区间，再释放来源；后续补采也必须经过同一过滤。删除同时清理相关观察、片段、证据、索引、修正和每日结果，并持久化时段或来源键排除，避免简单补采后重现。

| 保留与资源规则 | 当前实现 |
|---|---|
| 原始观察 | 30 天 |
| 通知正文/原始通知观察 | 7 天 |
| 诊断日志 | 7 天 |
| 非收藏片段 | 730 天 |
| 数据库软预算 | 800 MiB：降级通知正文及新照片索引 |
| 硬预算 | 约 1000 MiB 或可用空间低于 20 MiB：停止新增原始观察，标记缺口 |
| 故障处理 | 密钥不可用/数据库损坏时保留文件，不自动破坏性清库 |

## 8. 备份与增强协议

完整备份为 `.woarchive`：外层 `WOARCH01` 头、独立恢复码包装的随机 keyset、Tink `AES256_GCM_HKDF_1MB` 流式认证加密载荷。内部 ZIP 固定为 7 项，含 manifest、观察、片段、修正、地点、策略及每日视图；不含照片原图、原设备权限或 API 密钥。

恢复先完整认证到私有暂存文件，再检查固定文件名、重复/路径穿越、条目大小、计数和哈希，导入独立加密暂存数据库并检查完整性，最后在正式数据库单事务内替换。失败回滚；成功后保持停止状态，重新检查来源授权。跨设备原媒体 URI 清除，等待重新关联。

当前归档展开上限为 512 MiB；每类 JSONL 明细上限为 50,000 条。按范围完整备份的入口尚未实现。可读的每日 Markdown/JSON 导出默认移除通知正文、精确坐标和图片 URI。

## 1.3.0 连接与运行效率

“连接”默认显示应用搜索与真实图标；展开某个应用可以决定是否参与记录、是否解析脱敏通知文字。授权入口直接打开系统，无二次用途确认。日历只读取系统日历中已同步的事件；媒体只读取应用主动公开的媒体会话。安装、授权、开启来源和正在记录分别判断，不将“已安装”写成“账号已连接”。

华为运动健康单独标注账号数据尚未接入，提供打开运动健康与官方说明入口；手机硬件计步、Health Connect、华为账号健康数据是三条不同链路。完整接入前置条件见[华为说明](Huawei_Health_Integration.md)。

自动补采串行执行，30秒内的重复前台/后台请求合并，手动刷新强制执行；取消或异常不会进入成功冷却。切换日期只重建本地日视图。历史与规律仅在回忆、我的或趋势页加载。来源探测合并事务，仅实际变化才刷新UI；无关来源变化不重启传感器，关闭步数和定位后无需前台记录服务。没有新增唤醒锁或高频轮询。

连续步数和位置需要后台记录，通知/媒体依赖系统监听，应用使用/图库/日历可以补采。后台任务不是准时定时器，实际耗电和华为后台存活需真机验证。截图、操作路径和版本验收见[1.3.0说明](Connections_1.3.0.md)。


## 历史：1.3.1 图文首页与图表

以下为历史设计记录，默认首页现已由1.6.0大事件时间轴替代。

按用户提供的已安装界面截图调整首页结构：打开先看到凌晨、上午、下午、晚上的图文卡片；顶部只保留日期、记录状态与刷新。移除挡在时间线前的大摘要和统计卡。保留 Material 图标、紫色主色与浅灰背景，时段分别用紫、暖棕、青绿、玫瑰色图标和时间标签；深色使用对应亮色。

照片保持真实 MediaStore 缩略图，两列排列、时间标注；一张照片使用 3:2 比例，多于两张可展开全部，不丢弃隐藏照片的访问入口。左侧细线随卡片高度延伸，最后一个时段结束连线；卡片内应用图标可横向滚动并打开片段。

时间线之后依次为四项统计、每小时手机使用柱图、真实应用使用区间。小时图每格上限 60 分钟，基于既有区间并集和 asOf 截断；支持 23/25 小时归档日。点选柱子或前后按钮可查看精确时间段，未到的小时不能选择。无使用数据时保留“—”且不绘制零柱图；空白仅表示没有已记录的用量。

实现与验证见 [1.3.1说明](Photo_Home_1.3.1.md)。数据库、权限、华为账号接入状态与后台采集策略不变。
