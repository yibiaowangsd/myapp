# 1.6.0 · 大事件时间轴与随时间变化的背景

对应版本：1.6.0 / 10；包名 `com.personal.wo`；更新：2026-10-16（Asia/Shanghai）。

## 体验目标

打开仍然只有一条可左右转动的时间轴。卡片对应真实发生的一件事，按实际起点排序：例如09:19的一组影像、09:40–10:25的运动、20:10–21:00的媒体播放。首页不再按凌晨、上午、下午、晚上切四块；跨过12:00的同一事件不会被拆开。地点推测保留“推测”，不根据软件名称编造“工作、学习”等活动。

照片出现在事件卡片内；同时段、有关联的应用和小片段收进同一事件详情。首页应用门槛仍默认单次至少10分钟，可选5/10/20/30分钟。门槛只改变展示，不删记录、不改变统计。

## 事件形成规则

这些规则是透明的本地展示规则，不是AI对生活意义的判断。只使用已有可确认的时间区间和来源类型。

| 来源 | 形成首页事件的条件 | 合并边界 |
|---|---|---|
| 停留、睡眠 | 单段实际观察至少20分钟 | 同类型、同标题、同断言，相隔最多5分钟；合并范围最多6小时；单条更长的原始记录保留完整 |
| 地点间移动 | 单段至少10分钟 | 同上；保留推测标识 |
| 运动 | 单段至少5分钟 | 同上；不以手机静止推断睡眠或活动 |
| 应用 | 单段达到用户所选门槛，来源记录或已确认 | 先筛单段；相隔最多10分钟的长使用合并，整组最多120分钟；单条更长的会话保留完整 |
| 媒体 | 实际播放至少5分钟 | 与相近长应用按同样的有界规则组织；时间使用并集 |
| 照片、视频 | 每项已有影像记录都可出现 | 相隔最多30分钟，整组不超过90分钟；没有影像内容识别与场景命名 |
| 短使用、通知、步数等 | 不单独成为“大事件” | 完全位于某事件时间内时放入其详情，否则留在全天“全部片段” |

真实世界事件优先成为容器。完全位于其时间内的长应用、媒体和照片附在该事件下。运动、移动、停留、睡眠按此顺序选择拥有者；同优先级优先最小包含区间。不同类型的原始大事件可以各自存在，照片等补充证据只归属一次。跨越地点边界的长会话保留自己的完整事件，不在两张卡片里重复累计。

合并后的起止时间来自主要记录；相关小片段不能把边界越拉越长。同应用重叠区间取并集，真实空档不当使用时长。相邻短打开不相加凑门槛；相邻照片或应用的链条有整体跨度上限，不会把一整天吞成一张卡片。日累计步数不会拆成虚构的运动事件或按比例分配。

不满足大事件条件的记录仍在已有“全部片段”页面。首页底部和菜单均有入口；只有小片段时显示专门的空态及记录数量，不生成一张虚假的大事件。未来计划、未知和时钟冲突不成为首页经历；原始分类页面保留既有证据口径。

## 时间背景

背景根据当前浏览位置对应的事件时间变化，取归档时区，不取手机此刻的时钟。双向拖动时先在相邻事件的真实时间之间插值，再连续插值背景颜色，因此往回转也能平滑回到之前的光色。

色调从夜间蓝灰、晨光暖色、白昼浅蓝绿，过渡到暮色暖粉及夜色。它只是时钟驱动的视觉氛围，不声称反映当地日出日落或真实天气；没有天气网络请求。深色模式降低同一套色调的亮度。背景、卡片和文字颜色分开处理，保证事件标题、时间和照片仍可阅读。没有定时轮播或持续后台动画；只有浏览状态更新时重绘。

底部改为实际时间刻度，滑动选择最近的事件起点。日期选择、前后翻日、回到今天和双侧对称景深保留。两个事件恰好同一时间开始时，按来源类型和原片段ID区分稳定键，避免错开详情。

## 实现入口

- `core/DayChapters.kt`：纯事件投影；大事件种子、有限合并、独占证据归属、应用并集、影像引用、最近起点定位。`RecapPart`仅复用标题/起止/原片段容器，首页不调用`recapParts`固定四段逻辑。
- `ui/DayAtmosphere.kt`：从Pager连续位置映射归档时间，再映射原生Compose配色；背景和卡片使用各自可读文字色。
- `ui/DayDrumUi.kt`：原有共同画布、布局offset与对称景深不变；显示事件标题和实际起止、时间刻度、全天记录入口与事件详情。
- `ui/AppUi.kt`：详情用事件稳定ID定位，替代仅使用开始时间；沿用原有返回栈与日期保持。

没有数据库迁移、新权限、新后台服务或新依赖。两个变体共用原个人签名配置；本次仅构建并交付增强版Release。已有自动测试、构建记录和真实设备边界见[验证报告](Verification.md)。历史四时段设计见[1.5.0](Chapter_Timeline_1.5.0.md)，已不再驱动首页。
