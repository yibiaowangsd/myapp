# 2.2.1 私有数据同步修复

## 已确认的问题与边界

2.2 的发布器先逐个覆盖日文件，随后写记忆，最后写索引。任何一个日期生成失败、512KiB 校验失败、网络异常、配置/记忆修订变化，都会中断后续步骤。首次同步没有索引时，下次又会重复上传已成功的日期；已有索引时，先覆盖日期或删除文件再更新索引，也可能留下旧索引与新内容不一致。超过每批48天的已有日期还会从索引中被错误移除。后台错误未持久显示，HTTP 请求本身没有退避重试。

2026-10-27 通过授权 GitHub 连接确认：目标仓库私有；存在12个普通日文件，合计3943239字节，最大498592字节；索引和记忆原本缺失；提交历史存在多轮重复上传。最大文件尚未超过524288字节，不能据此将此次中断归因于容量限制。没有手机日志和同步状态，无法确认最初是哪一个异常触发了中断。

## 修复行为

- 将日文件、记忆、索引及撤回操作放入同一提交，最后非强制推进默认分支；索引与内容一起生效。读取固定在同一提交，冲突时保留并发写入者的版本并重新同步。
- 一批处理最多48个变化日期；暂缓的已有日期仍保留旧快照。无法生成的日期计入待同步，其余日期和记忆可以发布。
- 新发布器读取v1/v2索引，发布v2索引。大日期采用有序、带哈希的合法JSON分片，不删减事实或事件；普通旧日文件保持兼容。撤回或缩小日期时同批删除其旧分片。
- 没有索引时核对远端孤立日文件并接纳相同内容；重复同步不产生无意义提交。
- 对网络、服务器错误和明确限流进行有限退避；权限错误直接提示；发布响应丢失时重新核实分支。错误只包含固定文案和阶段，不回显响应体、令牌或生活内容。
- 开始同步时持久记录“尚未确认完整发布”；后台失败保存阶段错误；有待同步日期时不更新最近完整成功时间。

## 本次远端恢复

在私有仓库中使用一次提交重建了12天索引，逐个复核原始日文件哈希，并确认所有原日文件的Git blob SHA与大小保持不变。恢复索引采用v1，以便原有2.2客户端仍可读取；2.2.1下一次同步会迁移到v2。

远端原本没有记忆数据，故只能创建标准格式的空记忆占位。`wo/recovery.json` 明确标记 `empty-placeholder-awaiting-device-upload`。此占位不是从手机恢复的偏好、观察或回顾，也不能据此认定用户没有记忆。手机下一次成功同步后，应以索引所指向的真实记忆替换占位。

## 自动化与设备验收

回归测试覆盖超过48天续传、重复同步、v1迁移、孤立旧日文件接纳、日文件/记忆/索引失败的原子性、暂缓旧快照、单日期失败恢复、取消、Unicode大文件无损分片和哈希、私有访问控制、空仓库初始化、HTTP重试、并发提交以及发布响应丢失。

执行仓库 Android verification：核心测试、Android单元测试、lint、debug/release编译及数据库兼容性检查。构建与单元测试不等于真实手机上传成功。

真实设备仍需升级2.2.1并完成：首次/续传同步；修改一个日记录后重传；更新偏好或生成回顾后同步；断网恢复；后台补传。每步之后通过GitHub连接固定提交读取索引、所指日文件和记忆并校验哈希，核对手机状态与远端变化。无需向聊天发送访问令牌或个人生活明细。
