# DeepSeek 与长期记忆 · 2.2

在右上角「设置 → DeepSeek 与记忆」填写自己的 DeepSeek API Key，选择模型后保存并生成回顾。不增加聊天页，底部仍只有首页和成就。

## 如何记住

DeepSeek 官方 Chat Completions 接口没有持久会话状态，每次必须主动提供上下文。因此记忆由 App 管理，不依赖供应商的临时缓存：

- `notes`：本人填写的偏好与目标，最多4000字。
- `observations`：带日期依据的 AI 历史观察，明确属于推断，保留最近200条。
- `review`：最近一次完整回顾，含生成时间、记录截止日期和模型。

记忆保存在现有 SQLCipher 加密数据库，重启后继续使用。每次调用带入全部本人偏好、最近64条观察、上次回顾及最近最多30个有记录的日期。事件、事实和总上下文有长度预算，必要时减少较旧的日期；这不是无限上下文。完整历史仍由日记录保留，可通过 GitHub 按日期查询。

DeepSeek 返回 JSON 后先检查完整结束、长度和依据日期，再与请求前的记忆版本、记录策略版本比对，全部通过才事务写入。失败、截断、清空、删除或配置变化不会用旧响应覆盖记忆。不保存模型的 reasoning_content。

## 自动回顾

默认关闭。开启后 Android WorkManager 约每12小时检查一次，分析昨天及此前有记录的日期。同一归档时区与截止日期，发送前就记录尝试标记，至多自动尝试一次；失败可手动更新。记录暂停或停止时不自动请求。网络、电量及系统后台策略可能延后任务，不承诺固定时间。

保存配置会立即请求一次回顾。API 请求由自己的 DeepSeek 账户付费，DeepSeek 接收本次结构化记录和记忆。关闭 DeepSeek 会停用调用并保留记忆；手动「清空记忆」可清除偏好、观察和回顾，原始生活记录仍保留，再分析时可能形成新的观察。

## 与 ChatGPT 共用

原「数据互通」开启后，`wo/index.json` 的 `memory` 条目指向 `wo/memory.json`，内容为同一份持久记忆。ChatGPT 的 GitHub 连接获准访问该私有数据仓库后，可以读取它和日文件。App 是当前共享文件的写入端；ChatGPT 不会通过该文件自动回写 App。

这不等于将 DeepSeek、ChatGPT 两个账号各自的内置记忆合并，也不会自动把文件写入 ChatGPT 账号记忆。这里通过连接读取当前快照；跨对话可将仓库说明放在项目说明中。

同步仍遵守原来的私有仓库校验、分批重试和内容去重；2.2.1 将日文件、记忆与索引在同一次提交中发布，较大日期使用有序 JSON 分片。记忆清空会同步空快照。GitHub 提交历史可能保留之前的内容，暂停同步不会删除远端文件。

## 修正、删除和恢复

删除记录、撤回来源、更改过滤策略或修正片段时，保守清除 AI 推断与回顾，保留本人偏好。重复导入修正已有数据时清除受影响日期的推断，其他日期观察保留。进行中的旧请求无法复活已清除的记忆。

加密备份的 `policy.json` 新增可选 `memory`，旧归档仍可在新版中恢复；旧归档恢复时清空当前 AI 记忆。恢复最新归档可以保留偏好与观察。恢复新版归档请使用2.2或更新版本。DeepSeek API Key 与 GitHub 令牌不写入数据库归档或共享仓库，跨设备需要重新配置。

## 接口依据

- [多轮上下文与无状态接口](https://api-docs.deepseek.com/guides/multi_round_chat/)
- [Chat Completions API、JSON 输出和 finish_reason](https://api-docs.deepseek.com/api/create-chat-completion/)

固定请求地址 `https://api.deepseek.com/chat/completions`，禁止 HTTP 重定向。当前支持官方文档列出的 `deepseek-flash` 与 `deepseek-v4-pro`，使用非思考模式、非流式 JSON 输出。错误信息不回显服务端响应或密钥。真实服务联调需要用户在手机上填写自己的有效密钥。
