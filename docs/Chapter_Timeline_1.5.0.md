# 1.5.0 · 按时段回看的双向时间轴

对应版本：1.5.0 / 9；包名 `com.personal.wo`；更新：2026-10-16（Asia/Shanghai）。

## 用户目标与这次调整

保留可以左右转动、随景深浮现的时间轴。首页的内容回到原图文首页的总结粒度；不再把每次打开应用做成一张卡片。照片出现在轴内，过去的日期也可以直接回看。

上一版把实际卡片放在每个Pager子项内再横向移出其布局范围，原生模拟渲染中左侧卡片受到裁切，即使位于一天中间仍不对称；首页从第一条开始也缺少左侧日期入口。这次把可见卡片放入共同的Box，各卡片用布局offset围绕同一中心定位，图层处理透视、缩放和淡出；透明Pager保留原生手势、惯性吸附、稳定键、状态恢复与可访问操作。位移和旋转对左右取反，缩放、透明度、垂直位移保持一致。首页第一段左侧提供明确的前一天入口，不把昨晚伪装成今天的经历。

## 首页显示规则

| 内容 | 首页 | 点开时段 |
|---|---|---|
| 生活片段 | 按凌晨、上午、下午、晚上概括；保留推测说明 | 全部原始片段及证据入口 |
| 应用使用 | 默认单次至少10分钟；可改5/10/20/30分钟 | 包括短使用；保留真实开始/结束时间 |
| 同应用多次使用 | 先判断每一段是否达标，再按应用汇总；不把多次短打开凑成长使用 | 每个原始片段可打开 |
| 跨时段使用 | 达标会话按各时段实际交集显示；重叠取并集，空档不计时 | 原始完整会话 |
| 照片/视频 | 同时段直接展示最多两项缩略图和时间；更多项有数量提示 | 全部不同URI的影像，可进入原片段 |
| 步数 | 按报告区间末尾归属时段，数量不切分 | 原证据保留 |
| 未知、未来计划、时钟冲突 | 不放入首页经历 | 完整时间线维持原有分类和证据 |
| 只有短记录的时段 | 一张简短汇总，提示零散片段已收入详情 | 全部可查看 |

首页门槛是本地显示偏好，不影响采集、保留、日统计或导出。统计仍包含所有可信应用区间；日总量继续取区间并集。资料不充分时不补造运动、睡眠、地点或照片。照片缺少拍摄时间时沿用“添加”记录口径。

## 日期与导航

顶部日期打开原生日历，支持前一天、后一天和回到今天；不能进入未来日期。转筒首尾是清楚标注的日期入口，今天末尾显示“截至”时间。空日期有日期控制和无记录提示，不用虚构记录填充。

回忆月历选择日期后进入对应日期的转筒。时段详情 → 原片段 → 返回，按原顺序返回；统计返回也保留日期。切换日期时在新数据到达前显示加载状态，避免日期标题和记录内容不一致。时段使用起点作为稳定键，后台新增更早时段不改变正在看的时段。

## 实现与边界

- `DayChapters.kt`：纯展示投影、单段门槛、时段交集、并集、影像引用和刻度选择。复用归档时区及23/25小时日边界。
- `DayDrumUi.kt`：共同画布、左右对称`drumPose`、透明原生Pager、日期控件、门槛选项和时段详情。只有当前卡片暴露阅读语义，支持按钮和时间刻度替代拖动。
- `WoViewModel.kt`：界面门槛单独写入SharedPreferences；日期限制在归档时区的今天之前。
- `AppUi.kt`：时段详情路由、返回位置、历史月历直接进入时间轴；底部首页名改为“时间轴”。

沿用既有Material系统、真实应用图标与缩略图加载器，不添加新的后台服务、权限或网络请求。Room V1、加密密钥、SQLCipher启动修复及计步采集保持兼容。两个Release变体使用原个人签名，可覆盖升级。

自动检查、原生渲染与安装包签名证据见[验证报告](Verification.md)和[设计检查](../design-qa.md)。原生渲染是Robolectric API35的生产Compose组件，不是真机截图；不代表已验证目标华为设备的帧率、真实照片授权或后台耗电。

参考官方实现说明：[Compose Pager](https://developer.android.com/develop/ui/compose/layouts/pager)、[Compose日期选择](https://developer.android.com/develop/ui/compose/components/datepickers)。
